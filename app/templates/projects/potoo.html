01 · Project Overview

Potoo explores how mobile technology and game-inspired design can make nature observation more accessible. The concept brings together nearby outdoor places, a location-aware bird field guide, camera-based observation, and a longer-term idea for personal collections and exploration challenges.

The intended audience ranges from beginning naturalists and students to outdoor enthusiasts and experienced birdwatchers. A beginner should be able to use Potoo to learn what lives nearby and build identification confidence; a more experienced birder should be able to use local discovery tools and keep track of encounters. The design aims to make getting started feel approachable without removing the depth that makes nature observation rewarding.

The project began with a simple question: how can an app encourage someone to notice more of the natural world around them? Rather than making the phone the center of the experience, Potoo is intended to help users prepare for an outing, use the app briefly when useful, and then return their attention to the landscape, wildlife, and sounds around them.

Core design principle: Technology that knows when to get out of the way. Potoo should support curiosity and observation, not compete with the outdoors for attention.

02 · Current Build & Development Status

The current project is a runnable React Native application with working navigation, a location-aware bird field guide, and a functioning camera capture flow. Other parts of the experience are at different stages of prototyping. The distinction matters: Potoo is a working mobile prototype, not yet a fully connected observation platform.

Working App runtime The application launches and runs on a device or simulator.
Working Navigation Home screen feature navigation and bottom-tab navigation are implemented.
Working Field Guide Retrieves nearby bird species using device location and the iNaturalist API.
Working Camera Requests camera permission, displays a live camera view, captures an image, and allows retaking it.
In progress Explore map Uses Apple Maps with nature-oriented points of interest; the map experience is still being refined.
Prototype Collection & Quests These screens currently use sample content and are not connected to persistent user data.

Implementation snapshot

  • Application: React Native with Expo and JavaScript.
  • Navigation: React Navigation with a native stack and bottom-tab navigator.
  • Location: Expo Location requests foreground permission and retrieves the device's coordinates.
  • Species data: iNaturalist's species-count observations endpoint is used to retrieve nearby bird taxa.
  • Mapping: Apple Maps is the map provider currently used in the Explore screen.
  • Camera: Expo Camera provides permission handling, live preview, capture, and retake behavior.
  • Data persistence: No backend or persistent storage is currently connected. Collection and quest examples are prototype data.

Status reflects the latest development update provided for this portfolio page. Features may evolve as the prototype develops.

04 · Core Features & User Experience

📍 Explore Nearby In progress

An Apple Maps-based view intended to help users find parks, natural areas, and other outdoor points of interest. The current map implementation is present, with the discovery experience still being refined.

📖 Location-Aware Field Guide Working

Uses foreground location permission and the iNaturalist API to retrieve bird species observed within a local radius. Results include species names and observation counts, with search and refresh states.

📷 Observation Camera Working

Provides a live camera preview, permission request, photo capture, and retake flow. Capturing an image is implemented; automatic species identification and saving observations are not currently claimed as implemented.

🗂️ My Collection Sample data

A scrapbook-like place to represent a user's species discoveries and observation history. The current screen demonstrates the intended interface with sample profile and observation content.

🎯 Quests & Challenges Sample data

A game-inspired layer for optional outdoor goals and learning challenges. The current screen uses example tasks and progress values rather than a persistent quest system connected to real observations.

🧭 Simple Navigation Working

A home screen provides entry points to the main app areas, supported by a bottom-tab navigation structure for moving between screens.

The intended observation-to-identification journey

The original product plan describes an observation workflow that begins outside the app: a person notices a bird, watches and listens, and remembers useful details. Afterward, they can enter what they recall and work through guided clues about appearance, habitat, behavior, season, and calls before receiving feedback. The identified species can then become part of My Collection. This is an important part of the product vision, but the guided identification flow and saved observation system are not yet implemented in the current build.

Design choice: Potoo is not intended to reward constant phone use. Its game-like elements should give people reasons to explore, learn, and return outdoors—not encourage them to stare at a screen while wildlife is around.

A note on the larger product vision

The broader Potoo concept includes guided, clue-based identification after an observation: users recall details such as color, shape, habitat, behavior, season, or calls and use those clues to narrow down a species. This remains part of the intended experience rather than a feature represented as complete in the current app build.

05 · Design Direction & Research

Visual language

Potoo uses a soft aqua and blue-green palette, nature-inspired imagery, rounded interface elements, and translucent glass-style feature cards. The goal is to make the app feel welcoming and exploratory rather than like a dense scientific database.

Aqua & blue-green palette Glassmorphism Nature imagery Field-guide influence Mobile-first interface

Design inspiration and comparative analysis

Potoo draws inspiration from tools such as Merlin Bird ID and iNaturalist, while exploring a different combination of local discovery, beginner-friendly learning, and optional game-inspired progression.

Merlin Bird ID

A reference for accessible bird identification, species information, and helping people connect observations with likely species.

iNaturalist

A reference for location-linked biodiversity observations and community-supported species knowledge. Potoo currently uses its API for nearby bird species data.

What Potoo takes from existing nature apps

The original comparative research looked at Merlin Bird ID and iNaturalist to identify useful patterns as well as opportunities for a different experience.

Merlin Bird ID · Identification and learning

What informed Potoo: accessible identification tools, regional bird information, and useful species profiles.

Where Potoo differs: the concept adds optional quests, collection progression, and a more deliberate clue-based learning process rather than centering the whole experience on fast identification.

iNaturalist · Biodiversity and place

What informed Potoo: location-linked observations and the ability to explore organisms beyond birds. Its API also supplies nearby bird observation data to the current Field Guide.

Where Potoo differs: the interface aims to be more focused for beginners and to keep social posting and extended screen interaction out of the center of the experience.

User groups

Persona 1

The Beginner Naturalist

A student or casual walker who enjoys local parks but is still learning how to recognize birds.

Design need: approachable species information, useful local context, and low-friction exploration.

Persona 2

The Experienced Birder

An outdoor enthusiast who visits natural areas regularly and wants to discover new places and species.

Design need: relevant local discovery and tools that complement, rather than interrupt, observation.

Persona 3

The Casual Explorer

Someone who enjoys being outdoors but may not yet think of themselves as a naturalist.

Design need: clear entry points, approachable challenges, and a reason to keep exploring.

06 · Design Iteration & Development Process

Potoo developed through a sequence of wireframing, design review, prototype requirements, and revisions. The project documentation records not just the intended screens, but the reasoning behind changes to the map, Field Guide, collection, and observation experience.

From early wireframes to a more defined app structure

The early wireframes established Home as the starting point, with Explore, Field Guide, My Collection, and Quests as the four primary feature areas. The navigation plan also separated the main Observation flow and Profile from those feature screens. The later mockups explored a more distinctive visual language: a nature-themed home screen, map-based discovery, a botanical field-guide treatment for species pages, and a notebook or scrapbook style for personal records.

Design feedback translated into decisions

Home screen hierarchy

The initial home screen risked having too many competing elements. The design review called for a clearer visual hierarchy around search and the main exploration features.

More informative map

Map pins needed to communicate why a place was worth visiting. The proposed improvement was selectable markers with hotspot details and potentially observable species.

Richer species and collection screens

The Field Guide was planned around common and scientific names plus identification information. Collection cards were envisioned with species images, dates, locations, and observation counts.

Sprint milestones

Sprint 1 · Establish the app structure

Define persistent navigation, the Home dashboard, Explore map with placeholder markers, searchable Field Guide, sample Collection cards, and sample Quests. The test plan focused on launch, navigation, screen access, and the expected placeholder content.

Sprint 2 · Improve interaction and learning

Refine the Explore map so markers can reveal hotspot details and potentially observable birds. Improve searchable species details, and define a guided observation process in which users enter characteristics and work through identification questions before viewing a result.

How this connects to the current build: the running app now has working navigation, location-aware bird data in the Field Guide, and camera capture. The interactive discovery experience and guided identification workflow remain development priorities; the original sprint requirements document the intended behavior, not proof that every requirement is complete.

07 · Technical Implementation

Potoo is currently built as a mobile application using React Native and Expo. The code is organized around reusable React Native components and screen-level state, with native device capabilities used for location, mapping, and camera access.

Mobile application

  • React Native
  • Expo
  • JavaScript and React hooks/state
  • React Navigation: native stack and bottom tabs
  • Expo Blur and Linear Gradient for interface styling

Device and data integrations

  • Expo Location for foreground location permission and coordinates
  • Apple Maps for the Explore map
  • Expo Camera for live preview and photo capture
  • iNaturalist API for nearby bird species counts

How the Field Guide data flow works

  1. The app requests permission to access the user's foreground location.
  2. It retrieves the device's current coordinates and derives a readable area label.
  3. It sends a request to the iNaturalist species-counts endpoint, filtered to birds and a local radius.
  4. The response is transformed into a list of taxa with local observation counts.
  5. The screen sorts and displays the results, and supports searching and refreshing the list.
Current architecture boundary: Potoo does not yet have a backend or persistent storage layer. The Field Guide retrieves external observation data, but the Collection and Quests screens currently demonstrate sample content rather than storing a user's records.

Potential next architecture step

A future data layer could connect captured observations, identified species, collection entries, and quest progress. That would turn the current interface prototypes into a continuous user experience. This is a future development direction, not a claim about the current build.

08 · Development Priorities

Refine Explore

Continue developing the Apple Maps experience, focusing on useful outdoor points of interest and a clear map interaction model.

Connect observations

Design a data model and storage approach so camera captures and species records can become saved observations.

Make the collection real

Replace sample entries with a collection populated by the user's saved observations and identified species.

Build connected quests

Connect challenge completion and progress to actual observations, species discoveries, and visits to new places.

These priorities follow the current prototype's most important gap: the core screens exist, but they do not yet share a persistent record of what a user has seen and learned.

Long-term direction: Potoo sits at the intersection of mobile development, geospatial technology, biodiversity data, and nature education. The goal is to build technology that helps people develop a stronger relationship with the places and species around them.
